☁️ 1. AWS Security Log Analysis (AWS_log/)

「Amazon Athenaを活用した、AWSセキュリティ生ログの調査・分析リポジトリ」

📝 プロジェクト概要

AWS CloudTrail（API操作ログ）やVPC Flow Logs（ネットワーク通信ログ）などの「生のログデータ」と、それをAmazon Athenaで解析するためのSQLクエリ群をまとめたディレクトリです。
インフラの構築ではなく、出力されたログから「システム内で何が起きているか」を読み解く、セキュリティアナリスト視点の調査手法にフォーカスしています。

🔍 分析ユースケースとSQLクエリ

ログデータに対してAthenaで外部テーブルを定義し、実際のセキュリティインシデント調査を想定した高度なクエリを実行します。

• 不審なAPI操作の特定:
CloudTrailのログに対し、「誰が・いつ・どこから・何をしたか」を抽出するSQLを実行し、不正アクセスや意図しない権限変更などの脅威ハンティングを行います。

• ネットワークトラフィックの監視:
VPC Flow Logsを解析し、特定のVPC内で拒否（REJECT）された異常な通信や、許可されていないポートへのスキャン行為を可視化・トラッキングします。

🏨 2. AI-Driven Hotel Reservation Architectures (`hotel_folder/`)

「顧客体験（UX）とブランドコンテキストに応じた、2つの相反する外部向けインフラ設計」

📝 プロジェクト概要

ホテル業界における「顧客体験の方向性」と「企業文化（ブランド）」を起点に、相反する2つのインフラ・セキュリティアーキテクチャを設計し、Terraformで実装・比較検証したプロジェクトです。
最先端のAI（Amazon Bedrock）を導入する際、「誰に、どのようなホスピタリティを提供するか」によって、裏側のクラウドインフラの思想は根本から変わるべきというコンセプトを表現しています。

🏗️ 2つのアーキテクチャモデル

🏛️ Type-B: Ultimate Edition（伝統と格式のハイブリッド型）

• コンセプト: 「見えない防壁で、変わらぬ安心を守る」

• 想定モデル: 歴史ある高級ホテル。急激なシステムの変更がブランド毀損に繋がりかねない環境。

• 設計思想: ユーザーが触れるフロント画面や基幹DB（RDS）は従来の堅牢な3層構造を維持しつつ、セキュリティレイヤー（裏側）にのみAIの自律防衛機構を組み込むアプローチ。

🚀 Type-A: Ultimate Security Edition（完全適応のアジャイル型）

• コンセプト: 「摩擦ゼロ。言語もITスキルも問わない次世代コンシェルジュ」

• 想定モデル: インバウンドやデジタルネイティブをターゲットにした先端的なブティックホテル。

• 設計思想: 完全なサーバーレス（Bedrock Agent + Lambda + DynamoDB）によるオーケストレーション。`interface`（対話）・`tools/reader`（読取）・`execution/reservation`（書込）で関所を分離。詳細は [`hotel_folder/STRUCTURE.md`](hotel_folder/STRUCTURE.md)。

🦈 3. Offline Egress Traffic Analyzer (analysis_wireshark/)

「ローカルAI環境向け・完全オフラインEgress（外部向け）通信監査ツール」

📝 プロジェクト概要

ローカル環境で稼働させるAIモデル（LLM等）が、意図せず外部サーバーへ機密データを送信していないかを検証するためのパケット解析・監査ツールです。
「自端末のログを外部APIに渡さない」という**データ主権（Data Sovereignty）の原則に基づき、パケット解析からGeoIP/ASNの情報付加まで、すべての処理を完全オフライン（インターネット切断状態）**で実行できるアーキテクチャを採用しています。

💡 開発の背景と機能

ローカルLLMの背後で発生する未知のテレメトリ通信や、プロンプトインジェクションによる外部へのデータ流出リスクを監視するため、L3/L4層のパケットを直接キャプチャして可視化します。

• 自動Egress検知: プライベートIPからパブリックIPへ向かう通信のみを自動抽出。

• 完全オフライン脅威分析: MaxMind GeoLite2ローカルDBを統合し、外部APIに依存せず通信先の国名や組織名（ASN/ISP）を即座に特定。

• SOC向けレポート出力: 複数のPCAPファイルを自動集約し、集計結果をCSVレポートとして出力。

🏢 4. AI-Driven Internal Infrastructure Architectures (`hotel_folder/internal-infra/`)

「組織文化と働き方を起点にする、社内インフラの相反する2つの設計思想」

📝 プロジェクト概要

外向けホテル予約（`hotel_folder/`）と同じ設計哲学を社内インフラに適用した比較検証プロジェクトです。
外部向けシステムが「どんなホスピタリティを提供するか」で決まるように、社内インフラは**「どんな企業文化・働き方を支えるか」**によってインフラ・セキュリティの思想が根本から変わるべきである、というテーマをTerraformコード化しています。

🏗️ 2つの社内アーキテクチャモデル

🏛️ Type-B: Enterprise Edition（伝統・統制型）

• コンセプト: 「変えないことが信頼の証明。既存資産を守りながら、見えないところだけ進化する。」

• 想定組織: 大手日系製造業・金融・官公庁。長年稼働するオンプレミスサーバーとActive Directoryを持ち、急激な変化がコンプライアンス違反に直結する環境。

• 設計思想: 既存環境とAWSをハイブリッド接続し、社員には従来通りの操作感を提供しつつ、裏側の監視レイヤーのみをAI（Sentinel Enterprise）で強化。発見的統制と厳格な変更管理プロセスをインフラで強制します。

🚀 Type-A: Cloud-Native Edition（先端・自律型）

• コンセプト: 「VPNをなくす。場所を問わない。IDだけを信頼する。」

• 想定組織: SaaS系スタートアップ・フルリモート組織。レガシー資産を持たず、全員がMacBookとSlackで働く環境ような環境。

• 設計思想: VPNを廃止し、AWS Verified Accessを活用したID・デバイスベースのアクセス制御（ZTNA）を実現。開発者がガードレールの範囲内で自由にリソースをプロビジョニングできる環境を整え、セキュリティをコード（Policy as Code）として予防的統制に寄せます。

📊 社内インフラ比較表

比較項目	Type-B（伝統・統制型）	Type-A（先端・自律型）
既存資産	Active Directory・オンプレサーバーあり	クラウドネイティブ・レガシーなし
ネットワーク	閉域網ハイブリッド（Direct Connect + VPN）	VPNなし・AWS Verified Access（ZTNA）
ID 管理	AD Connectorによる既存AD連携	IAM Identity Center + SCIM連携
開発者体験	承認プロセス必須・厳格な変更管理	開発者セルフサービス・Guardrails内で自由
セキュリティ	検知・対応型（重要度別ルーティング）	予防・自動化型（そもそも侵入させない設計）
AI の役割	脅威の自律検知・エスカレーション	セルフサービスポータルや社内RAGのアシスト

🛡️ 共通セキュリティ基盤への取り組み

全プロジェクトを通じて、エンタープライズ水準のガバナンスを見据えたセキュリティベースラインを意識しています。

• KMS / 権限管理: カスタムキー（CMK）の利用と自動ローテーション、最小権限の原則に基づく厳格なIAMポリシー設計。

• トレーサビリティ: CloudTrailやVPC Flow Logsによる操作・トラフィックの完全な記録と可視化。

• サプライチェーン監視: DependabotやCIパイプラインを通じた、コード・依存パッケージの継続的な脆弱性スキャン。
